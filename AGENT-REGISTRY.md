## 2. Обязательный порядок перед работой (каждый агент, каждая сессия)

```bash
# 1. Реестр против живого git (код выхода 1 = есть расхождения)
curl -sSf https://raw.githubusercontent.com/lordos2003/chain-love/agent-registry/registry_check.py -o registry_check.py
python3 registry_check.py

# 2. Все ветки форка и их головы
git ls-remote --heads https://github.com/lordos2003/chain-love.git

# 3. Все PR upstream (head = ветка, merge-реф есть = PR открыт)
git ls-remote https://github.com/Chain-Love/chain-love.git 'refs/pull/*/head' 'refs/pull/*/merge'
```

Затем:
- Прочитай таблицы ниже. Твоя область (категория.колонка, сеть, офферы) НЕ должна пересекаться с «открыта»/«заявлена» строкой.
- Проверь дубли по ячейкам сканером (открытые PR upstream + ветки форка без PR; ~1–2 мин):
  ```bash
  curl -sSf https://raw.githubusercontent.com/lordos2003/chain-love/agent-registry/dup_scan.py -o dup_scan.py
  python3 dup_scan.py --cat <категория> --col <колонка> [--col ...] [--net avalanche] [--free]
  # свои PR/ветки исключить: --exclude-pr 4455 --exclude-branch fill-avalanche-misc
  ```
  «ЗАНЯТО» = ячейка пуста в upstream main и непуста в добавленной строке чужого PR или ветки. Такие ячейки не трогать. `--free` выводит свободные ячейки офферов. Повторить скан прямо перед коммитом.
- Если пересечение есть или что-то непонятно: остановись, не создавай ветку, спроси Олега.

## 3. Заявка (claim) до начала работы

1. Выбери имя ветки: `<глагол>-<сеть/область>-<категория>[-N]`, например `fill-avalanche-audits`, `add-ramps-tags`. Имя должно быть уникальным среди веток форка.
2. Добавь строку в таблицу «Заявки» (статус `claimed`): ветка, область (файл.колонка, сеть), агент/сессия, дата-время МСК.
3. Запушь реестр (`git pull --rebase` перед пушем; одна строка = одна ветка; при конфликте пересобери свою строку).
4. Только после этого создавай ветку работы. Заявка без ветки старше 24 часов считается протухшей: можно спросить Олега и снять.

## 4. Во время и после работы

- Одна ветка = один владелец. В чужую ветку не коммитить, не force-push, не удалять, не переименовывать, не пересоздавать.
- После пуша обнови строку: `head` (7 символов), статус (`ready` = готово к PR, `open` = PR открыт, `merged`, `closed`).
- Номер PR вписывает тот, кто его узнал (Олег открывает PR сам; скрипт `registry_check.py` показывает номер по SHA головы).
- Перед каждым коммитом/пушем в ветку, которую уже видят ревьюеры, сверься с реестром ещё раз (кто-то мог её сдвинуть).

## 4а. Подпись коммитов (обязательно с 2026-10-19)

В конце сообщения КАЖДОГО коммита в форк строка-трейлер:

```
Agent: <имя агента>/<id сессии или запуска>
```

Примеры: `Agent: claude-code/session_01EzVCFG42JqmQZQcBAF3i7T`, `Agent: claude-scheduled/trig_017Z6qurpaEwKs8oyXkp2eA4`, `Agent: mavis/<id>`. Трейлер ставится отдельным абзацем вместе с остальными (`Co-Authored-By:`, `Claude-Session:`). `registry_check.py` показывает Agent из head-коммита каждой ветки и предупреждает о ветках без него. Ветка без `Agent:` считается неопознанной: прежде чем в ней что-то делать, спросить Олега.
